# 오픈소스 소프트웨어 텀프로젝트

## 주제 선정
평소에 피아노를 한번씩 연주하는데 새로운 악보를 연주할 때마다 음이 익숙하지 않아 맞는 음을 연주해도 불협화음처럼 들리는 때가 종종 있었음. 이럴 때마다 악보만 있어도 원래 연주를 들어볼 수 있는 소프트웨어가 있었으면 좋겠다고 생각함. 그래서 '악보를 바탕으로 미디파일을 만들어주는 소프트웨어'라는 주제를 선정함.

## 1일차
OpenCV 알고리즘을 이용하기 위해 악보 색 반전을 통한 이진화된 악보 생성 구현. 이진화된 악보에서 오선 / 음표 및 악상기호들을 분리하여 새로운 이미지로 생성.

## 2일차
복잡한 악보를 넣었더니 악보 전처리가 이상하게 되고 해상도가 많이 떨어졌음. 코드를 다시 구성하였지만
여전히 같은 문제가 반복됨. 아예 구조를 처음부터 다시 설계했지만 여전히 음표 인식에서 문제가 생김

## 3일차
musicXML오픈소스를 활용해 악보 이미지의 미디 전환 확인
해당 과정에서 필요한 라이선스들을 정리함

## 4일차
GUI의 기본 기능을 구현함.
악보 이미지 추가 - PNG, JPG, JPEG, TIF, TIFF 파일을 선택할 수 있음. 여러 파일을 한 번에 추가할 수 있고, 같은 파일이 중복으로 들어가는 것은 안됨
선택한 악보 삭제 - 목록에서 선택한 파일을 대기열에서 제거함
저장 폴더 선택 - MIDI 파일을 저장할 폴더를 지정할 수 있음. 기본 폴더는 프로젝트의 outputs폴더
대기열 순차 변환 - 악보를 한 장씩 차례로 변환 변환 중에도 창이 멈추지 않도록 별도 작업 스레드에서 처리합니다.
파일별 결과 표시 - 목록에 각 파일의 변환 중, 완료 또는 실패 상태를 표시함 한 파일이 실패해도 다음 파일을 계속 처리함
전체 진행률 표시 - 대기열 중 몇 퍼센트까지 처리했는지 표시함
기존 결과 보호 - 같은 이름의 MIDI 파일이 저장 폴더에 이미 있으면 _2, _3처럼 번호를 붙여 저장함
변환 중 조작 제한 - 작업이 진행되는 동안 파일 목록이나 저장 폴더를 바꾸지 못하게 하고, 변환 중 창을 닫으려 하면 안내알림 등장함

## 5일차
사용자가 GUI에서 Audiveris.exe의 경로를 직접 선택할 수 있는 기능을 추가함, 잘못된 경로가 지정되면 변환 전에
안내 메세지를 표시하도록 함
Audiveris의 출력을 CP949로 읽으면서 오류가 발생했는데, Audiveris의 출력을 바이트 형태로 받아서 UTF-8로 변환하도록 수정함.
처음 작은별 악보를 테스트해봤을 때 악보 해상도가 낮아 오선 간격을 6픽셀로 판단하여 처리를 중단함.
이미지 긴 쪽이 1600픽셀보다 작으면 자동으로 확대하도록 전처리를 추가함. 이후 변환된 미디파일이 잘 저장되는 것을 확인함.

## 6일차
악보 이미지를 여러장 입력하여 MIDI파일 하나로 변환하는 기능을 구현함.
해당 과정에서 단순한 양손악보는 변환에 문제가 없지만 복잡한 악보를 샘플로 사용하면 음이 밀리거나 악기소리가
달라지는 등 다양한 문제가 발생함. 이미지(jpg, png)뿐만 아니라 pdf파일도 악보로 입력할 수 있는 기능을 구현하고
확장자는 여러개 중복해서 사용이 불가하도록 설정함. 악기소리를 피아노소리로 고정함.

## 7일차
여러 페이지로 구성된 피아노 악보 PDF를 MIDI로 변환하는 기능을 점검함. Audiveris가 오른손과 왼손의 마디 길이를 서로 다르게 인식하면서 연주 시점이 점점 어긋나는 문제를 확인함.
이를 개선하기 위해 오른손과 왼손이 동일한 마디 시작점을 사용하도록 리듬 보정 코드를 수정함. 그 결과 마디 단위의 누적 싱크 오차는 줄일 수 있었음.
추가로 악보인식 과정에서 발생한 문제일 수도 있어서 악보를 단순히 확대하여 Audiveris가 인식할 수 있도록
한 것이 아닌 전처리 코드를 따로 추가하여 gui와 연결함.
하지만 16분음표가 포함된 마디나 악상기호가 많은 복잡한 구간에서는 음표가 정확한 박자에 연주되지 않는 문제가 남아 있었음.

## 8일차
원래는 이미지만 전처리를 진행하였지만 PDF도 각 페이지를 300DPI 이미지로 변환해 전처리하도록 기능을 추가함. 초기에는 명암 보정과 선명화 처리를 적용했으나, 가는 음표 꼬리와 빔이 손상되어 기존에 인식되던 음표가 누락되는 문제가 발생함. 이를 해결하기 위해 과한 전처리를 제거하고 그레이스케일 변환과 저해상도 확대만 사용하도록 변경함. 또한 JPEG 압축이 적용되는 임시 PDF 대신 손실 없는 다중 페이지 TIFF를 Audiveris에 전달하도록 수정함.
MIDI에서 음이 밀리는 문제를 개선하기 위해 마디별 공통 시작점을 설정하고, 정해진 박자보다 길게 인식된 마디를 자동 보정하는 기능을 추가함. 보정 과정에서 마디 전체를 일정 비율로 압축하면 16분음표가 0.25박이 아닌 0.222…박처럼 변해 싱크가 더 어긋날 수 있음. 그래서 마디 전체를 압축하지 않고, 잘못 인식된 개별 음표의 길이를 표준 박자값으로 보정한 뒤 이후 음표의 시작 위치를 재배치하도록 구현함.
현재는 16분음표가 많은 구간에서 일부 음표가 누락되는 문제가 남아 있음.

## 9일차
PDF 악보를 300DPI, 400DPI, 원본 PDF로 각각 인식하고, 각 인식 결과를 비교해 짧은 음표가 더 많이 검출된 마디를 선택하도록 수정함. 이음줄이 없는 반복음이 하나로 붙어버리는 문제가 발생하여 해당 음 사이에 짧은 공백을 추가해 따로 연주되도록 수정함. 진짜 이음줄로 연결된 음은 분리하지 않도록 예외 처리를 추가함. 빔이 사용된 마디에서 8분음표가 4분음표로 잘못 변환되고 뒤쪽 음표가 누락되는 현상을 발견했는데, Audiveris의 No timeOffset 오류로 인해 인식된 음표가 MusicXML에서 제외되는 문제를 확인함. Audiveris 버전을 낮춰서 별도로 실행해 비교했지만, 5.11.0과 동일한 오류가 발생하는 것을 확인함. No timeOffset이 발생한 페이지, 마디, 파트를 자동으로 검출하도록 구현함.인식이 불확실한 위치를 .review.txt 파일로 저장하고 GUI 경고창에서 보여주도록 개선함. 리듬처리 코드가 너무 길어져서 3개의 소스코드로 분할함.

## 10일차
빔으로 연결된 부분의 음이 자꾸 누락되는 오류가 있어서 빔으로 연결된 부분을 따로 관리하는 소스코드를 만들어  실제 MIDI 변환 과정에 연결함. 빔과 음표 기둥을 분석해 연결된 8분음표·16분음표의 누락을 복구하도록 개선함. 기존 음표가 4분음표로 잘못 인식된 경우 음표 길이와 연주 시점을 교정하고, 오인식을 방지하기 위해 4개 이상 연결된 빔 음표 묶음만 자동 보정하도록 제한함. 실제 샘플 악보 중 빔으로 연결된 부분 중에 누락이 계속 발생했던 문제 구간에서 누락 음표 4개를 복구하고 기존 음표 4개의 박자를 교정함. 변환 완료 창에 오류 내용을 띄우지 않고 오류 내용을 따로 txt파일로 만들어서 사용자가 확이해볼 수 있도록 함. 자세한 보정 및 오류 내용은 MIDI와 같은 이름의 .txt 파일에 저장하도록 통합함.

## 11일차
셋잇단음표의 리듬이 자동으로 이상하게 보정되는 문제를 셋잇단음표가 포함된 마디의 예외처리를 통해 해결함. 빔 음표 복구 후 마디의 박자에 빈틈이나 겹침이 발생하면 보정 전 상태로 복원하도록 안전장치를 추가함. GUI에서 20~300 범위의 BPM을 설정할 수 있는 기능을 추가함. 마지막 짧은 오선을 연장하는 전처리가 다른 정상 마디의 인식에 영향을 주는 원인을 발견했고, 원본 보존 악보를 기본 인식에 사용하고, 오선을 연장한 악보는 마지막 마디 복구용 보조 인식에만 사용하도록 변경함. 잘못 인식되던 부분이 A4 점8분음표 → G4 16분음표 → F4 4분음표로 정상 변환되는 것을 확인함.

## 12일차
같은 개수의 음표가 인식된 경우에도 보조 인식 결과의 박자가 더 정확하면 해당 마디를 교체하도록 수정함. 분산되어 연주되어야 할 화음이 하나로 뭉쳐서 연주되는 문제가 있어서 이를 해결함. 음이 다음 마디까지 밀리던 문제를 수정함.
미–시–미 셋잇단음표가 한 박자에 동시에 연주되는 문제가 발생했고, 기존에는 0.5박 이하의 음표만 복구했지만 셋잇단음표의 길이인 2/3박까지 복구 대상으로 포함하도록 변경함. 잘못 인식된 화음을 순차적인 셋잇단음표로 교체하는 회귀 테스트를 추가함.

## 13일차
빔 인식 문제를 해결해보려 했으나 해결하지 못함. musicxml파일도 함께 저장되도록 하였음. musicxml파일을 통해 사용자가 직접 수정이 가능하기 때문에 실용적임.

## 14일차
Audiveris를 완전히 대체하지 않고, 오류가 의심되는 음표를 PyTorch 모델로 재검사하는 구조를 설계함. 원본 PDF 또는 악보 이미지와 MusicXML을 비교하여 음표 후보 이미지를 자동으로 추출하는 ml_dataset.py를 추가함. 기존 beam_recovery.py의 오선 검출, 음표 후보 검출, 마디 좌표 계산 기능을 재사용하였고, 각 음표 후보를 32×32 흑백 이미지로 저장하고 위치, 페이지, 마디, 파트, 검출 신뢰도를 labels.csv에 기록하도록 구현함. 고해상도 PDF에서 일부 오선을 놓치는 문제를 발견하여, MusicXML의 예상 오선 개수와 수평선 점수를 이용해 필요한 오선을 선택하도록 개선함.
MusicXML과 위치가 확실하게 일치하는 후보는 notehead 폴더에 저장하고, 확실하지 않은 후보는 잘못 학습되는 것을 방지하기 위해 review 폴더에 분리함. 데이터 생성 방법과 주의 사항을 README에 추가하고 명령줄 실행 기능을 등록함.

## 15일차
학습 데이터 검토 GUI를 구현함. 32×32 음표 후보 이미지를 320×320으로 확대하여 확인할 수 있도록 구성했고, 음표로 분류, 비음표로 분류, 후보 건너뛰기, 마짐가 분류 되돌리기 단축키를 만들었음. 후보를 분류할 때 이미지가 notehead, other, review 폴더 사이에서 이동하고 labels.csv가 즉시 갱신되도록 구현함. 프로그램을 종료했다가 다시 실행해도 남아 있는 review 후보부터 계속 검토할 수 있도록 함. 검토 진행률과 남은 후보 개수를 GUI에 표시하도록 함.작은 PyTorch CNN 기반 음표 분류 모델을 구현함. 음표와 비음표 데이터의 개수가 다를 경우 적은 클래스의 개수에 맞춰 균형 있게 학습하도록 구성함. 전체 데이터 일부를 검증 데이터로 자동 분리하고, 검증 정확도가 가장 높은 모델을 저장하도록 구현함. PyTorch를 선택적 ML 의존성으로 추가하고 모델 학습 방법을 README에 작성했다.

## 16일차
기존 데이터를 확인한 결과 실제 음표가 비음표로 잘못 분류된 사례가 다수 발견되어서, 검토 GUI에 비음표 다시 검토 기능을 추가하여 기존 라벨을 다시 확인할 수 있도록 함. 판정할 후보의 중심을 빨간 상자로 표시하도록 하였고 음표와 비음표를 구분지었음. 원본 악보에서 후보 주변을 넓게 잘라 보여주도록 수정함. 검토 GUI에 학습 모델의 추천 결과와 확률을 표시하도록 함. 모델 추천이 맞으면 Enter로 적용하고, 틀리면 1 또는 2로 직접 분류할 수 있도록 함. 분류 정확도가 처음엔 66%였지만 현재 92%로 개선됨.

## 17일차
다른 악보를 활용해 모델 학습 예정
